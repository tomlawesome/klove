# Live-control negative-test catalogue

## Status and use

This is test design for [issue #135](https://github.com/tomlawesome/klove/issues/135).
It does not authorize a live-control transport, an operation, a policy value,
or an executable test.  Under [ADR 0001](decisions/0001-typed-job-control.md),
temperature, speed, fan, light, motion, extrusion, arbitrary G-code, and every
other actuator remain prohibited.  A future accepted live-control ADR must
select the applicable rows before implementation starts.
[ADR 0009](decisions/0009-grove-mqtt-compatibility.md) is proposed and also
does not authorize those controls or provide their transport.

In this catalogue, **deny before dispatch** means no typed actuator request is
attempted.  **Fence as `outcome_unknown`** means the request may have reached
the printer: retain the durable reservation, return only the bounded uncertain
result, and make no second request.  These are result classes, not proposed
public error-code names.

Every new actuator requires 100% statement and branch coverage across
authentication, authorization, control, decoding, translation, and policy.
The implementation must cover every catalogue row selected by, or applicable
to, its accepted ADR.

## Reusable fixture kit

| Fixture | Minimum evidence and controls | Reused by |
| --- | --- | --- |
| `auth_context` | An unauthenticated request plus authenticated principals with absent, malformed, expired, wrong-principal, missing-scope, wrong-scope, and cross-printer-scope evidence.  Scope strings are placeholders supplied only by the future ADR; the fixture never defines public vocabulary or exposes credentials. | LC-A01--LC-A03 |
| `two_printers` | Two canonical printer UUIDs, independent routes, credentials held outside assertions, capability snapshots, state tokens, profiles, mappings, and journals.  The fixture records the target UUID for every read and attempted request. | LC-A02, LC-03, LC-12, LC-13, LC-16--LC-18, LC-D01--LC-D03 |
| `live_evidence` | Current cached evidence plus a direct-poll script that can change one identity, phase, capability fingerprint, generation, limit, or state token at each read boundary. | LC-03--LC-09, LC-18 |
| `mapping_profile` | Explicit operator-confirmed semantic role-to-object or reviewed-contract mapping, allowlist, safety-profile generation and fingerprint.  It can be absent, ambiguous, stale, or changed. | LC-04--LC-05, LC-08--LC-11 |
| `typed_adapter_recorder` | A future-ADR-specific fake transport that records one exact typed request and can lose a response without disclosing credentials or request bodies.  It has no generic G-code entry point. | LC-A01--LC-A03, LC-01--LC-11, LC-14--LC-20, LC-D01--LC-D03 |
| `shared_gate` | A cancellable per-printer gate with barriers before proof, reservation, dispatch, reconciliation, registry commit, and runtime handoff. | LC-12--LC-13, LC-15--LC-18 |
| `durable_fence_store` | Isolated registry catalogue and owner journal with exact installation/store identities, schema-version variants, orphan/missing/wrong-owner references, fault injection after each committed write, restart/reconnect construction, bounded inspection, and an attempted-request counter that survives the test process.  Parameterized owner identity is added only after an accepted ADR/schema amendment defines it. | LC-12, LC-14--LC-18, LC-D01--LC-D03 |
| `diagnostic_sink` | A bounded public result and a separately inspectable sanitized diagnostic capture.  Inputs include long hostile text, invalid encodings, and secret-shaped values; assertions check lengths and absence, never the secret value. | LC-10, LC-19A--LC-20 |

The fixture kit describes test observability only.  It does not select request
methods, units, limits, macro semantics, credentials, or recovery policy.

## Interpretation of existing coverage

The cited tests are overlap, not completion evidence.  They exercise accepted
job-control, print-start, registry, and shared-gate contracts.  They do not
authorize reusing their transport, their process-local journal semantics, or
their operation-specific postconditions for live controls.  In particular,
`tests/unit/test_control_service.py` currently retains uncertainty in process
memory, while [ADR 0013](decisions/0013-durable-actuator-fence-references.md)
requires a future durable control journal and registry-owned fence catalogue.
ADR 0013 also closes `fence_kind` to `control`, `print_start`, or
`coordinator`, and `owner_store` to `control_journal`, `start_journal`, or
`dispatch_journal`.  Its current control identity covers the parameter-free
pause, resume, and cancel operations; it defines no immutable parameter
identity for a live-control reservation.  Neither closed vocabulary nor owner
schema may be silently extended for this catalogue.

## ADR decisions still required

1. **Live-control safety envelope.** Issue [#15](https://github.com/tomlawesome/klove/issues/15) remains open.  An accepted ADR must decide the permitted operations, caller authorization and exact scope, allowable phases and transitions, residual multi-client race treatment, evidence freshness, and which controls can proceed.  This catalogue does not choose any of them.
2. **Temperature and speed.** Issue [#16](https://github.com/tomlawesome/klove/issues/16) specifies the intended outcome but has no accepted transport/policy ADR.  It must define the typed operation, canonical parameter representation and units, discovered/configured-limit interpretation, safety-margin semantics, exact capability proof, and operation-specific postcondition before LC-08--LC-11 and LC-18 can become executable tests.
3. **Fan and light.** Issue [#20](https://github.com/tomlawesome/klove/issues/20) likewise requires an accepted ADR for the typed transport, allowed object or reviewed macro contract, confirmation provenance, mapping lifecycle, allowed values/transitions, and postcondition.  This catalogue does not infer macro semantics from a name.
4. **Durable live-control ownership.** [ADR 0013](decisions/0013-durable-actuator-fence-references.md) accepts closed owner/fence kinds and a durable parameter-free control identity, but its control journal and catalogue runtime remain follow-on work.  Before any parameterized actuator uses that boundary, a live-control ADR and schema amendment must explicitly define its typed operation and immutable parameter ownership, compatibility, migration, restart, restore, and reconciliation rules.  It must also explicitly amend any closed owner/fence vocabulary it changes; parameter data cannot be hidden in an existing identifier.  The amendment may not invent a recovery clear, expiry, or retry.
5. **Diagnostics and confirmation contract.** The future ADR must define the public result vocabulary, which exact evidence can confirm each live operation, and the applicable bounded diagnostic and confirmation limits.  The catalogue requires the negative properties above but does not select numbers, logging fields, or a transport.
